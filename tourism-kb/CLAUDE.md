# CLAUDE.md — Tourism KB

Guidance for Claude Code when working inside `tourism-kb/`. This file is nested:
it auto-loads **in addition to** the repo-root `CLAUDE.md` whenever you work in
this subtree. Root working-principles and PII rules still apply; this file scopes
them to the tourism product and carries its own mistake log.

## What this is

A **separate offline product** that shares the bus-booking repo and nothing else.
It builds a Đà Lạt trip-advisory knowledge base for an **AI consultant reader**
(not a traveller). It imports nothing from `lib/`, touches no database, and no
app code (`app/`, `lib/`, `components/`) references any path under here — the
coupling is zero. `public/tourism/*.jpg` belongs to the BUS APP (charter-rental
carousel), not to this product; do not touch it.

"First script data for the AI data lookup" — Đà Lạt now, more destinations later.

## Working Principles

Same four as root `CLAUDE.md` (Think Before Coding · Simplicity First · Surgical

## The Guards — read before touching any output path

Everything this pipeline generates carries **real Vietnamese mobile numbers**
(~14,328 under `raw/`, 416 under `wiki/`). For a one-person business the
"business number" IS a personal mobile, and this repo is toggled **PUBLIC during
`/ship`**, so a mis-placed generated file = published PII. Four coupled layers keep
it out, and they reference paths **by string** — change one, change all in the
same commit, or the protection silently disarms:

1. **`code/duong_dan_ra.py`** — write-guard. `THU_MUC_CHO_PHEP = ("tourism-kb/raw",
   "tourism-kb/wiki", "tourism-kb/output")`. `kiem_loi_ra(path)` raises `SystemExit(1)`
   before any write outside those roots; every builder calls it. Tested both
   directions by `code/test_duong_dan_ra.py`.
2. **`G8`** in `../scripts/audit/greppable-invariants.sh` (`check_g8_tourism_artifacts`)
   — fails CI if `git ls-files` finds anything tracked under `tourism-kb/{raw,wiki,
   output}`, any `*.docx`, any guide basename anywhere, or `tourism-kb/code/*.json`.
   The write-guard stops a file being born in the wrong place; G8 stops it reaching
   a push. Neither subsumes the other.
3. **`tourism-kb/.gitignore`** — the by-location/by-type ignore rules.
4. **`../.github/workflows/ci.yml`** — runs `test_xep_hang.py` + `test_duong_dan_ra.py`;
   `../.gitleaks.toml` carries the `\+84[35789]\d{8}` phone rule.

Prove a guard fires before trusting it: run `test_duong_dan_ra.py` (both
directions) and confirm G8 both PASSes clean and FAILs on a forced `git add -f`.

## PII Discipline

- Phone numbers ARE the value (every row needs a verify call) — they stay, but
  stay OUT of git.
- No posts, account names, or faces stored (PDPL 2025 has no "publicly posted"
  exemption). Only public business data, no login, no technical bypass.
- No rating scores stored — only `place_id` (Google) / Location ID (TripAdvisor).
  Ranking rules live in files (`xep_hang.py`, Wilson thresholds); the numbers do
  not. No hotel star grades (`GIA_3SAO` is a price convention, say so at each site).
- Commercial prices → `gia_tham_khao` with every conflicting value shown.

- **2026-08-01 (I designed a ranking scale anchored to one hand-picked reference row, and my own portability test broke it: same 172 rows, different anchor → tier A went 12 → 27)** — Building a reusable eatery ranking for 63 provinces, I anchored everything on a benchmark establishment: floor `n ≥ max(n₀/100, 30)`, tier `CL = Wilson(R,n)/Wilson(R₀,n₀)`. It looked principled — the user names the standard, everything scales to it. The measurement that killed it took one loop: hold the 172 measured rows fixed and vary only the benchmark. `n₀=11.364 → 12` tier-A · `3.000 → 14` · `800 → 19` · `200 → 27`. A 125% swing in the headline number with **zero change to the underlying data**. Cause named by a review agent and confirmed: `n₀` is the **maximum** of a heavily right-skewed distribution (median 60, max 11.364 — a 189× spread), and the maximum is the least stable statistic available; letting it drive *both* the evidence floor *and* the score scale means the whole table pivots on one observation. Across 63 provinces "hạng A" would silently mean something different in every province. **Rule: a threshold or scale derived from a single extreme-valued row (max, top-1, "the famous one") is not a standard — it is a sample of size one, and it will not reproduce. Calibrate thresholds against the reference ONCE, then freeze them as absolute constants; never recompute the scale per dataset. Greppable smell: any scoring function taking a `moc`/`benchmark`/`reference` parameter that appears in the denominator, and any floor written as a fraction of another row's value.** Fixed by removing the benchmark from `xep_hang.xep()` entirely — it now takes `(R, n)` and nothing else, with `NGUONG = ((4.70,"A"),(4.40,"B"),(4.00,"C"))` and `SAN_TOI_THIEU = 30` as national constants; the user's chosen reference still sets the bar in effect (`Nậm Nướng` 4,9★/11.364 → W=4,888 → A) but no longer *is* the bar. **Two further corrections in the same pass, both mine, both found by writing the test before trusting the code.** (1) I diagnosed the wrong defect: I claimed `CL = W/W₀` compresses the quality axis. Measured at fixed n=2.000, the steps are ~0,065 per 0,3★ — essentially linear, no compression. The real defect is different and worse: at high `R`, the binomial variance `p(1−p)` collapses, so Wilson barely penalises small `n` — which is why `5,0★/167` scores **above** `4,9★/11.364`. That is why the evidence floor exists and must not be removed; Wilson alone does not close that case. **A plausible mechanism stated without measurement is a hypothesis, and I have now shipped one as a diagnosis twice.** (2) My own test asserted `"moc" not in xep.__code__.co_varnames` to prove the benchmark was gone — it failed, because `co_varnames` includes **loop variables** and the function body has `for moc, ten in NGUONG`. The test was inspecting locals while claiming to inspect the signature; correct form is `co_varnames[:co_argcount]`. Same shape as the 31/07 entry: **a failing self-written check is evidence about the pair (test, code), and twice now the test was the wrong half.** The other failing assertion was also mine — I expected `3,9★/221 → C` from the *previous* threshold set (4,5/4,0/3,5) after choosing 4,7/4,4/4,0. But tracing that one surfaced a genuine design hole worth more than the test: `hang=None` was carrying **two different meanings** — *below the evidence floor* and *above the floor but below every tier*. Split into `DUOI_CHUAN = "—"` (a conclusion) versus `None` (a gap), which is the 28/07 "could not test ≠ tested and failed" rule arriving at the tiering step.
