# spent 28 non-refundable YouTube calls on a lodging sweep that returned `Du Lịch Đà Lạt`, `Tp Đà Lạt` and `Khách Sạn Giá Rẻ` as the top "notable hotels" — and ZERO of the 413 price-bearing registered ones

Ported the eatery vlog sweep to lodging (`sweep_youtube_luutru.py`). Dictionary built fine: 4.866 names, tier A = 413 state-registered lodgings that carry price, tier B = 4.453 Overture rows. 28 queries, every one returning 20-25 videos and 4-45 matches, exit 0. The result is unusable, and the headline number says why: **0 of 39 rows above the ≥2-channel threshold came from tier A** — the entire point of the exercise was hotels *by price tier*, and the price-bearing half of the dictionary matched nothing. What did match: `Du Lịch Đà Lạt` (36 channels — "Đà Lạt tourism"), `Tp Đà Lạt` / `Tp. Đà Lạt` (11 + 6 — "Đà Lạt City"), `Khách Sạn Giá Rẻ` (7 — literally "cheap hotel"), `Khách sạn Đà Lạt giá rẻ` (6 — **verbatim one of my own query strings**), `Thung lũng Tình Yêu` (6 — a tourist *attraction*), `Bất động sản Đà Lạt` (3 — a real-estate agency), `vườn hoa Đà Lạt` (2 — a flower garden). Three distinct causes, and only the first was foreseeable from the existing log: (1) **My `CHUNG` stopword set was hand-written and small** — the 2026-07-28 entry already says a hand-written stopword list always misses the local filler words and must be derived from corpus token frequency. I wrote 19 words from intuition. (2) But deriving it does **not** rescue this: measured document frequency over all 5.157 lodging names and applied a >0.5% cutoff — it rejects only **8 of the 39**, leaving `Tp Đà Lạt` (distinctive token `tp`), `Khách Sạn Giá Rẻ` (`re`), `Thung lũng Tình Yêu`, `Bất động sản Đà Lạt` (`bat`). Frequency cannot separate them because they genuinely contain low-frequency tokens; the eatery sweep only worked because dish names gave it a **second, independent axis** (`MON_TU`, derived from a curated dish list) and **lodging has no analogue** — there is no "dish" for a hotel. (3) The sharpest and entirely new failure: **the query vocabulary IS the business-name vocabulary.** Restaurants named after dishes were a known trap, guarded by requiring a token outside the dish set. For lodging, businesses name themselves after the exact phrases people search (`Khách sạn Đà Lạt giá rẻ`), so a query and a business name can be the same string — no token-level rule can separate a shop from the query that found it. **Rule: before porting a name-matching pipeline to a new entity class, check whether the discriminating axis it depends on EXISTS in the new class. The eatery matcher rests on dish-tokens as an independent axis; lodging has none, and no amount of stopword tuning substitutes for a missing axis. And check whether the entity class names itself after the search vocabulary — when a plausible query string is also a plausible business name, presence-matching is structurally unable to tell them apart, and the fix is not a better filter but a different signal. Greppable smell: a second `sweep_*` reusing a first one's matching strategy where the first one's discriminator (a curated label set, a category vocabulary) has no counterpart in the new domain.** Second-order finding, the one that actually settles it: **0/413 tier-A matches is not a threshold problem, it is a naming problem** — the register stores `Khách sạn Đà Lạt Palace Herita…`, `Khách sạn Du Parc Đà Lạt`, while vloggers say "Dalat Palace", "Du Parc". `Dalat Palace Heritage Hotel` *did* clear the threshold, but as a tier-B Overture row with no price attached, so it cannot be tiered. This is the same 17%-name-join gap measured before the run (72/420 exact-name matches between register and Overture, only 45 with a price) reappearing one layer up — I measured that gap, designed around it by making tier A the primary dictionary, and still did not draw the conclusion that *if registered names don't match Overture names, they won't match spoken names either*. **Decision: the lodging vlog layer is NOT published.** `luutru_vlog.json` is kept as evidence of the negative result, wired into nothing. Hotels stay presented as they are — price tier, room count, phone, address, state-appraisal flag — with no notability claim, because none of the available signals supports one. Cost of the lesson: 28 of 100 daily calls. Cheaper than publishing a hotel table whose top entry is the phrase "Đà Lạt tourism".
