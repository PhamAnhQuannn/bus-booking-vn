[SECURITY / SECRET SCANNER — proven bypass] `scripts/audit/secret-scan-staged.sh:11,19-22`

    FILES=$(git diff --cached --name-only --diff-filter=ACM)
    ...
      if grep -I -n -E "$pattern" "$f" >/dev/null 2>&1; then

  The hook takes **staged filenames** and then greps the **working-tree file**.
  Index content is never read. Any divergence between index and worktree is a
  hole, and `git add` followed by further editing is the single most common git
  workflow there is (`git add -p` creates the divergence by design).

  **[empirical]** In a throwaway repo: stage a file containing
  `AKIA-ZZZZZZZZZZZZZZZZ` (gạch nối thêm vào để hook không tự chặn chính báo cáo này), then overwrite the worktree copy with `clean now`.
  `git show :staged_only.txt` still returns the key. Scanner output: nothing,
  `EXIT=0`. The commit would carry the secret with a green hook.

  The inverse also fires: an unstaged secret sitting in the worktree blocks an
  unrelated commit, which is how a team learns to type `--no-verify`.

  Fix: scan the staged blob, not the path —
  `git show ":$f" | grep -I -n -E "$pattern"` (and drop the `[ -f "$f" ]` guard,
  which is meaningless once you read from the index).

[SECURITY / SECRET SCANNER — silent skip on ordinary paths] `scripts/audit/secret-scan-staged.sh:11,19,20`

    for f in $FILES; do
      [ -f "$f" ] || continue

  `$FILES` is a newline-joined list expanded unquoted, so it word-splits. Two
  entire classes of path are then dropped **without a single line of output**:

  1. any path containing a space — splits into fragments, each fails `-f`;
  2. any path with a non-ASCII character — `git diff --name-only` emits it
     double-quoted and octal-escaped (`"t\303\240i-li\341\273\207u..."`), so
     `-f` fails on the literal quotes.

  **[empirical]** Same throwaway repo, 12 staged files each containing a planted
  secret. Exactly **one** was reported. `sub dir/leak with space.txt` and
  `tài-liệu-bí-mật.txt` — both holding the identical AWS key that *was* caught
  in `plain.txt` — produced no output at all.

  Class 2 is not hypothetical for this PR: the work it ships is Vietnamese, and
  the generated artifacts in the author's own tree are `Huong-Dan-Da-Lat.docx`
  only because they were transliterated by hand.

  Fix: `git diff --cached -z --name-only --diff-filter=ACMR | while IFS= read -r -d '' f`,
  and set `core.quotePath=false` (or use `-z`, which suppresses quoting).

[PRIVACY / MISTAKE-LOG PATTERN — the guard has no positive assertion that it fired] `scripts/tourism/fb_pages_crawl.mts:107-122`
