PRIORITY 2 — Fix before merge:

  [SCOPE / AC COVERAGE] PR says "Closes #349" but implements one of two prescribed remedies
    Issue #349's `## Fix` reads:
      "Relabel to 'Nhà xe đăng nhập' (operator login) **and/or move it into the
       partner/operator group, mirroring how `SiteFooter.tsx` already segregates operator
       links — so customers are not invited to an admin login.**"
    The PR does the relabel and nothing else. The second half is not cosmetic overlap — it is
    the half that addresses *prominence*: the header still hands operator login the site's
    single strongest affordance, and below `xl` (which includes the `mobile-390` Playwright
    project) that affordance is an **icon-only solid-orange pill with no visible text**
    (`SiteHeader.tsx:264-274`, `CTA_CLASS`). A sighted mobile customer's experience is
    byte-for-byte unchanged by this PR. `and/or` makes shipping one half defensible, but the
    body never states that the grouping half was considered and deferred, so "Closes #349"
    will auto-close an issue whose reported symptom still reproduces at 390px.
    Fix: either narrow to "Refs #349" and keep the issue open for the grouping/prominence
    half, or add a line to the body stating the deferral and why. (Cross-ref: same underlying
    defect logged as P2-1 in `docs/qa/code-review-pr355-20260726.md`.)

  [NEGATIVE SPACE / TEST] user-visible copy constant changed, zero assertions added
    No trigger row in the standard negative-space table fires literally — no schema change, no
    env var, no new route handler, no dep, no flag, no cron, no external call. But the diff's
    entire payload *is* a user-facing string, and grep across `e2e/**` + `**/*.test.tsx` finds
    **no test anywhere referencing `SiteHeader`, the CTA label, or the header's `/op/login`
    link**. The absence is demonstrably load-bearing: `docs/design/mockup-home-spec.md:100,227`
    has specified `Đăng nhập nhà xe → /op/login` since it was authored, and `master` shipped
    `Đăng nhập / Đăng ký` regardless — this string already drifted once, undetected, and this
    PR restores it with no guard against drifting back. The repo already runs Playwright on
    both `chromium` and `mobile-390` (`playwright.config.ts:16-23`), so the harness cost is one
    line in an existing customer-facing spec.
    Fix: add the assertion in this PR (`getByRole('link', { name: 'Đăng nhập nhà xe' })`
    → `toHaveAttribute('href', '/op/login')`), which resolves via `aria-label` on mobile and
    therefore covers both render paths.

  [PR DESC / TEST-PLAN ACCURACY] body's verification claim overstates what mobile renders
    `## Verify` says: "Visual: homepage header desktop + mobile nav shows the operator-login
    label." On mobile the **header** does not show the label — the `xl:hidden` cluster renders
    `<LogInIcon>` with the label only as `aria-label`. The text appears solely inside the
    opened drawer. If "mobile nav" means the drawer the claim is technically true, but the
    sentence reads as "verified on desktop and mobile header" and a reviewer will take it that
    way — masking precisely the gap flagged above.
    Fix: reword to state exactly where the label is and is not visible ("desktop header +
    mobile drawer; the sub-xl header CTA remains icon-only with the label as `aria-label`").
    That single edit converts the weakest part of the PR from hidden to explicit.
