  [SCOPE / ISSUE AC] PR body: "Closes #327"
    Issue #327 is titled "Orphan PaymentEvent backlog: **metric + alert**" and its body asks
    for "a counter/metric **on orphan creation** + held/unresolved counts". It was filed as a
    deferred **obs-review P1** off #324, whose whole complaint was that the backlog fires no
    alert anywhere.
    This PR delivers the metric half only: a read-time `paymentEvent.count()` rendered as a
    passive admin tile. The diff contains ZERO observability emission — no `captureMessage`,
    no counter at the orphan write site (`lib/payment/processWebhook.ts:117`
    `recordUnmatchedPaymentEvent`), no threshold, no page/email. A tile that requires a human
    to load `/admin` is not an alert; if nobody opens the console, the backlog is exactly as
    invisible as before for the push-notification purpose #327 was raised for.
    `Closes #327` will auto-close the issue on merge and retire the alerting half silently —
    the same documentation-drift-into-permanent-history failure the 2026-07-24 mistake-log
    entry warns about for squash-merges.
    Fix: downgrade to `Refs #327` and leave the issue open for the alert half, OR add the
    emission (a `captureMessage` fingerprint at `recordUnmatchedPaymentEvent`, or a threshold
    check in the existing cron) in this PR. Either is fine; silently closing is not.

  [TEST PLAN] PR body `## Verify`
    Reads in full: "`pnpm vitest run lib/admin/__tests__/getFailureAlerts.test.ts` → 4/4;
    `tsc` + `lint` clean." That is evidence for the pure-function half only. Two gaps:
      a) This PR changes a **rendered page**. `app/admin/(console)/page.tsx` goes from 2 tiles
         to 4 inside a `sm:grid-cols-2` grid, with three new Vietnamese labels. No screenshot,

      b) This PR modifies a **domain barrel** (`lib/notification/index.ts`) and imports it into

         Here it is genuinely safe (`getFailureAlerts.ts` has no `'use client'`, so the barrel

    No full-suite `pnpm test` result is claimed either, despite the interface change
    (`FailureAlerts.failedNotifications` removed).
    Fix: add to `## Verify` — full `pnpm test` result, plus one `/admin` render (screenshot or
