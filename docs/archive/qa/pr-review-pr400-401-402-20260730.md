## Findings

### P2

**[CLAIM] "Gate" is not a gate.** The body's own thesis — quoting #333 — is that *"a gate that emits nothing is not evidence of health."* The recursive case is unaddressed: a check whose failure blocks nothing is not a gate either. `master` has no branch protection and no required contexts, so a red `Python Syntax` job is advisory. This is not a reason to reject the PR (the check is still worth having), but the title, the commit subject and the body all use "gate" unqualified, and that becomes master's permanent claim. Either add one line — *"advisory until `master` gets required checks"* — or pair the PR with enabling `Python Syntax` as a required context.

**[CORRECTNESS] The checker walks the filesystem, not git, while its docstring says "tracked".** Consequences: (a) locally it parses untracked scratch files CI will never see — there are two in this tree right now; (b) any vendored/virtualenv Python not named `venv` / `.venv` fails a developer's run; (c) it recurses *into* `node_modules` before filtering it out, so the advertised local command is slow in this repo. One-line fix that removes all three and makes the local and CI file sets identical:
```python
files = subprocess.run(["git","ls-files","*.py"], cwd=root, capture_output=True, text=True).stdout.split()
```
If the filesystem walk is deliberate (to catch files staged-but-not-committed), say so and correct the docstring — but do not leave the docstring asserting a mechanism the code does not use. Per this repo's own 2026-07-30 entry: *"a comment explaining why a file or branch exists is not evidence that it still runs."*

### P3

- `actions/setup-python@v5` is the only action version in the diff with no in-repo corroboration (the file otherwise uses `@v7` throughout — `checkout@v7` ×9, `setup-node@v7`). setup-python versions independently so this is probably right, but it is the one unchecked value.
- No `paths:` filter — the job runs on docs-only and lockfile-only pushes. Cheap, but so is `paths: ['**/*.py', '.github/workflows/ci.yml']`.
- No rollback line. Trivially true here (revert two files, nothing deployed, nothing installed) — but the body states everything else, so its absence reads as an oversight rather than a judgement.
- Body has no `## Summary` / `## Test plan` headings.

### Explicitly good — preserve on squash

The body says, of the incident that motivated the PR: *"**This gate would not have caught that one.** It was semantic, not syntactic, and I'd rather say so than oversell it."* That is the correct disclosure and the opposite of the #399 failure mode. It should survive the squash verbatim.

The `others == 0` self-exclusion is the strongest thing in this PR. A naive `checked == 0` guard could never fire — because `root` derives from the script's own path, the glob always matches at least the script — and the body says the author only noticed while testing. That is a real, non-obvious defect caught before merge, and the fix is right.

## Negative space — is skipping the pre-commit hook the right call?

**Yes.** `python -c` startup plus a full-tree `rglob` on every commit, to catch a class that CI catches within a minute, is the wrong trade for a hook that already runs `lint` + `tsc`. The asymmetry is that Python here is *scripts*, not shipped product — nothing in `app/`, `lib/` or `components/` imports it, so a broken `.py` cannot break a build or a deploy. CI is the correct layer. The body asks the question rather than deciding silently, which is the right posture.

## Scope discipline — position

**Exemplary.** One intent (`ci:`), two files, +104/−0, no unrelated churn, no drive-by fixes. This is the shape the other two should aim at.

## Verdict — **MERGE**

After: (a) fix the "tracked" docstring or switch to `git ls-files`, (b) one clause noting the check is advisory until `master` has required checks. Neither is blocking if the reviewer accepts them as follow-ups. Merge this **first** of the three — it costs nothing and it exists before #399's 39 additional `.py` files arrive.
